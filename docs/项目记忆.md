# Pek.ZDsMallUI（Zig）· 架构与坑

### 目录与模块根

- 与 C# 同构：`Areas/Admin/Controllers/{AdminArea,HomeController,ConfigController,LoginController}.zig`、
  `Areas/Admin/Views/**`、`Controllers/UploadController.zig`、`Views/Shared/**`、`assets/**`。
- **模块根必须是仓库根的 `pek_zdsmallui.zig`**：Zig 的 `@import`/`@embedFile` 不能跨模块根目录，
  而 C# 同构目录把代码放在 `src/` 之外。`build.zig` 的 `addModule` 指向该文件。
- 视图/配置改用 `@embedFile("../Areas/...")`、`@embedFile("../../assets/ueconfig.json")`；
  原先的两个「只为嵌入而生」的模块（Views/embed.zig、assets/embed.zig）已删除。

### 控制器约定

- 动作签名 `fn (self: ?*anyopaque, c: *zzig.web.router.Ctx) !ActionResult`，`self` 一律是 `*AdminArea`。
- 视图统一由 `src/views.zig` 的 `Views`（单一 ViewRenderer + 缓存）渲染，不用 Controller 自带渲染器。
- `AdminArea.mount` 负责把 Home/Config/Login 三个控制器挂到 `/{area}/...`。

### zzig 行为要点

- **中间件只在命中路由或设置 fallback 时执行**；`/Upload/downloads/{深路径}` 用
  `app.router.fallback`（上传目录 → app.statics → 404）。
- `ViewRenderer` 原生支持 `Areas/{Area}/Views/...` 与 `setFallbackArea("Admin")`。
- `StaticFiles` 磁盘文件默认流式（`Response.file`）；ETag 是弱 ETag，304 由库测试覆盖。

### Razor 子集限制

- `@section` 体内遇到 `}` 即结束 → 内联 JS 必须外置（`assets/admin-config.js`）。
- `@{ // 注释 }` 不支持 → 用 `@* ... *@`。
- `@if` 条件必须布尔；缺键渲染失败 → `views.withTemplateDefaults` 先补默认键。
- **视图必须声明 `@{ Layout = "Shared/_Layout"; }`**，否则渲染出的是片段（无 `</html>`）。
- **`@expr` 后不能紧跟全角标点**（`@Model.areaName（…）` 会把后续整段吞掉）→ 用 `<code>@Model.x</code>` 或加空格。

### 口令与安全

- `src/password.zig` 复刻 C# `SaltPasswordProvider`：`$算法$盐$散列`，默认 **`md5+sha1`**
  （C# 默认 `sha512` 只认明文，会丢「前端先 MD5」能力）；五种算法全支持、旧式明文/MD5 可验证并自动升级。
- **三方互通对拍（2026-11-19）**：C# 实测命令
  `DH.RustBase\tools\csharp\DHRustDemo.exe password-hash-fixed <alg> <pwd> <salt>`；
  `src/password.zig` 的 `CSHARP_GOLDEN` 锁死 5 种算法（`New#life` + 盐 `abCD12./xyZ9012Q`）与
  中文口令 `中文口令123`。C# 的 `Verify` 对 **32 位 hex（大小写都认）** 返回 OK（实测），
  Zig 用 `hexDecode→HMAC` 实现同一支路。
- **前端 MD5**：`assets/login-md5.js`（标准 MD5 + `TextEncoder`）由 `materializeDefaults()` 落地到
  `wwwroot/static/admin/js/login-md5.js`；提交前把口令替换成小写 32 hex；后端同时收明文与 MD5。
- **界面样式**：一律复用参考 `admin.css` 的类名；自造的 `assets/admin-ui.css` 已删除
  （`materializeDefaults` 还会主动清理旧的 `wwwroot/static/admin/css/admin-ui.css`）。
- 上传校验顺序：扩展名白名单（空 = 全拒）→ 体积上限（配置与全局取小）→ 路径格式化 → 越界校验 → 落盘。
- 抓取：只允许 http/https，20 秒超时（`zzig.Http.fetchBytesWithTimeout`），最多 10 个来源。
- 面板不得用原生 `alert`/`confirm`/`prompt`；设置页校验改为就地提示。

### 登录 / 退出 / JWT（`src/auth.zig`）

- **复用 `Pek.ZPermissions`**（路径依赖 `../Pek.ZPermissions`，模块名 `pek_zpermissions`）：
  HS256，与 C# `NewLife.Web.JwtBuilder` / Rust `Pek.RPermissions` 字节级互通；**不要自己写 HMAC**。
- 声明：`sub`（uid 文本）、`name`（登录名）、`displayName`、`isAdmin`；库注入 `iss`/`exp`/`iat`/`jti`。
- 取令牌顺序：**Cookie `{area}_token` 优先 → `Authorization: Bearer`**（`Pek.ZPermissions.http_auth.Guard`
  只认 Bearer，所以 Cookie 解析写在 `auth.tokenOf`）。
- 登出 = `Keeper.revoke(token, now)` 写吊销表 + `Set-Cookie … Max-Age=0`；**只删 Cookie 不算登出**。
- 中间件在 `AdminArea.mount` **最先**注册：写链路状态 `auth.uid` / `user` / `auth.token`
  （`user` 即模板 `@Model.userName`）。`Builder.requireLogin(true)` 才拦截（302 到登录页并带 `returnUrl`），
  默认 `false`（与 C#/Rust 现状一致）。
- `Builder`：`jwtSecret` / `jwtIssuer` / `jwtExpireMinutes`（默认 120 分钟）/ `requireLogin` /
  `cookieSecure` / `sessionStore`（默认内存 `MemoryStore`）；未配密钥 → 进程内随机 + WARN（重启旧令牌失效）。
- 路由：`POST|GET /{area}/login/logout`、`GET /{area}/login/status`（`{authenticated,userName,isAdmin,expiresAt,uid}`）。

- **幂等建表用 `Pek.ZCode`**（`G:\Code\Zig\Pek.ZCode`）：`EntityModel.parse` → `Dal.initWithModel`
  → `Dal.syncSchema`（缺表建/缺列补/缺索引建，**不删列不改类型**）。本库模型在
  `assets/zdsmallui-model.xml`；**别再手写 `CREATE TABLE`**。
  实测：模型加一列 → 重启自动补列且老数据保留。
  坑：① 每请求 `Dal.openSession()` 单条 INSERT ~1.1s（方言探测+建连）→ 运行期用 `zzig.db.sqlite` 直连；
  ② `Session` **不可按值长期持有**（内部 arena 失效 → prepare 段错误），要么局部 `var s = ... defer s.deinit()`，
  要么放堆上（已在 Pek.ZCode `Session.init` 注明）。

### WAF / SQLite / 真实 IP（2026-11-19 二轮）

- **`G:\Code\Zig\Pek.ZWaf` 存在**（爬虫分级/注入/CSRF/IP 名单/CC/限流/规则引擎/早拒）。
  接入：`Builder.waf(base_dir)` → `mount` 首行 `useMiddleware(waf.middleware())`，
  示例再挂 `pek_zwaf.ServerGuard.init(waf, srv.ctx, srv.handler)` + `install(&srv)`。
  **别再说「Zig 侧没有 WAF」**（上一轮已因这句话被纠正）。
- **反代是常态**：zzig `trust_forwarded_for` 默认 `true`（仍只在对端是回环/`trusted_proxy_prefixes` 时采纳）；
  ZWaf `trustForwardedFor` 同样默认 `true`（否则 loopbackBypass 会把反代流量整体豁免）。
- **`RequestView.remote_addr` 现在是纯 IP**（原来 `ip:port`）：WAF/限流/审计/登录守卫直接用，不要再剥端口。
- **SQLite 默认持久化**：`Builder.storage(dir)` → `{dir}/{Area}.db`，幂等建表 `Setting`/`AdminUser`，
  种子 `admin/admin123`；驱动不可用时回退内存并打 ERR。
  实测「保存设置 → 杀进程重启 → 值仍在」。
- **zzig sqlite 两个坑（已修，`bd561b5`）**：① `prepare` 必须持有 SQL 副本（sqlite 不复制 SQL）；
  ② `readRow` 必须在 `stmt.hasRow()`/`step()` 之后调用，否则列值全是 `.null`。
  另外 `Db` 必须持有 `*Lib` 指向**稳定地址**（把栈上 `Lib` 复制进结构体会段错误）。

### 安全基线（2026-11-19）

- **zzig 默认安全头**：`server.Options.security_headers = true` → `x-content-type-options: nosniff`、
  `x-frame-options: SAMEORIGIN`、`referrer-policy: no-referrer`（含 413/500 与静态资源、文件流）。
  业务同名头会被库覆盖；**CSP 不默认开**（会打到内联脚本/CDN）。
- **真实 IP**：`server.Options.trust_forwarded_for = false`（默认）。反代后必须设 `true`，
  才在「TCP 对端是回环」时采纳 `x-real-ip` → `x-forwarded-for` **末段**；否则 IP 恒为 `127.0.0.1`。
- **登录防爆破** `src/login_guard.zig`：同 IP 10 次 / 同用户 5 次失败 → 封禁 5 分钟，成功清零；
  键统一小写、不硬锁账号、条目上限 4096；命中直接 business `code=429`（**HTTP 仍 200**，沿用 C# 约定）。
  参数走 `Builder.loginGuardOptions(.{...})`。
- **静态资源缓存**：`zzig.web.Options.static_cache_control`（默认 `null` = `no-cache`）；
  示例设 `public, max-age=600`，ETag/304 仍生效（实测 304）。
- 刻意不做：WAF（Zig 侧无 pek_rwaf 等价物）、Slowloris 读超时（要包装 `std.Io.Reader` vtable）、CSP。

### 服务端 keep-alive（zzig，2026-11-19）

- `zzig.http.server.Options`：`keep_alive=true`（默认）、`keep_alive_requests=100`、`keep_alive_timeout_secs=5`、
  `max_connections=512`（原 64 太小：浏览器同域 6 连接，正常并发就拒连白屏）。
- `serveWithLimit()` 在同一 socket 上连续 `receiveHead`；`serveOne()` = `serveWithLimit(stream, 1)`。
  每个响应后**必须显式 `flush()`**（已内置），否则数据滞留写缓冲、客户端死等。
- 实测（`/biz/login/index`，.NET HttpClient 串行）：200 请求 2.47×、500 请求 2.18×；RSS 7.1 MB。
- **回环测试写法**：别「写请求→读响应→再写请求」（会在第一次读时阻塞），
  改一次性 pipelining 写完再读；curl/.NET 对同一服务正常。`zig build test` 会吞测试进程输出，
  卡住时直接跑 build runner 打印的 `zig test -Odebug -Mroot=src/zzig.zig ...` 才看得见进度。
- **线程模型别重复造**：zzig 已有 `threading.pool`（线程池）与 gRPC 侧的 `ConnDispatch{thread_per_conn,task}`
  事件循环范式（万连接 24 线程 / 0 拒连）；HTTP 侧要对齐需单独一轮，不要自写线程池。
